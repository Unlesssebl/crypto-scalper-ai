# Crypto Scalper AI

Локальный форк [HyperData Terminal](https://github.com/Co-Messi/HyperData-Terminal) на ветке `crypto-scalper`. Базовый коммит `5fd1f0264391de1b65b18014049ea61161d82d51` закреплён тегом `scalper-upstream-base`. Для просмотра обновлений upstream выполните `git fetch upstream` и `git log --oneline scalper-upstream-base..upstream/main`.

## Единое управление

`start.ps1` теперь управляет native API, скринером и всем Market Pulse вместе.
Используйте `--status`, `--restart`, `--stop`; обычный запуск работает в фоне,
а `--tui` — в текущем терминале. Полная актуальная инструкция —
[unified-project.md](unified-project.md).

## Режимы выполнения

`start.ps1` (и `start.sh`) запускает единый контур: `PULSE_UNIFIED=1` для native API
и screener. В нём native Hub владеет биржевыми сокетами и L2, Market Pulse —
исполнениями, screener — единственный автор плана attention. Направленный legacy AI
и его очереди не запускаются; Telegram-карточки идут через `CardOutbox`/Telegram UX.

`--without-pulse` (или `PULSE_UNIFIED=0`) — явный legacy-режим совместимости.
Только в нём действуют `HYPERDATA_ATTENTION_ENABLED`, Top-20 и старый направленный AI.
Не смешивайте режимы на одном журнале.

## Быстрый старт

Нужен Python 3.12 или новее. Из каталога форка выполните одну команду:

```powershell
.\start.ps1
```

Скрипт сам подготовит окружение, установит пакет, скопирует `.env.example` в `.env`, запустит нативный HyperData API на `8420`, внешний screener на `8421` и Market Pulse на `8431`. Откройте [панель Crypto Scalper](http://127.0.0.1:8421/scalper). Для явного legacy-режима без Market Pulse используйте `.\start.ps1 --without-pulse`.

На Linux и macOS используйте `./start.sh`.

Если установлен [uv](https://docs.astral.sh/uv/), скрипт использует его: окружение и зависимости готовит uv, а не `pip`. Без uv всё работает через `.venv`. Логи нативного API пишутся в `.runtime/native.log`.

### Режимы

| Команда | Что получится |
|---|---|
| `.\start.ps1` | Unified: native API `8420` + screener `8421` + Market Pulse |
| `.\start.ps1 --without-pulse` | Явный legacy-режим: native API + screener без Pulse |
| `.\start.ps1 --tui` | Плюс Rich Market Overview в терминале |
| `.\start.ps1 --demo` | Синтетические данные, без Gemini и Telegram |
| `.\start.ps1 --port 8500` | Другой порт screener |
| `.\start.ps1 --api-port 8500` | Другой порт native API |
| `.\start.ps1 --notify` | Telegram-уведомления, если заданы токен и chat id |
| `.\start.ps1 --help` | Все флаги лаунчера |

В legacy-режиме колонки 1M AI и 5M AI показывают итог сравнения и возраст принятого снимка; в unified они остаются историческим архивом.

### TUI (`--tui`)

Экран показывает:

- **шапку с health badge и меткой потока**: `✓ LIVE` / `⚠ PARTIAL` / `⚠ STALE`, `Flow: HL` или `HL + BN`;
- таблицу топ-инструментов с колонками AI;
- панель **ORDER FLOW** — CVD/OFI и `venue=combined` из `/v1/orderflow`;
- панель **NATIVE CONTEXT** — L/S, basis, IV, ликвидации, whales, funding
  (это же покрывает нативную панель Market Intel);
- панели **LIQUIDATIONS**, **DANGER ZONE**, **LARGEST POSITIONS**;
- **HLP VAULT** — AUM, PnL, net delta и Z-score, позиции, поглощения;
- **LIQ HEATMAP** — USD ликвидаций по ценовым уровням вокруг цены;
- **SMART MONEY** — агрегаты кошельков и последние follow/fade-сигналы
  (без адресов: только ранг, win rate, confidence, PnL).

Сигналы скринера считаются по Hyperliquid-окну (parity), а панель ORDER FLOW
показывает combined-окно из `/v1/orderflow`. Когда Binance даёт сделки, CVD
там может отличаться — метка `venue` это явно показывает.

`screen`-режим Rich не прокручивается, поэтому экран подстраивается под высоту
терминала. На терминалах ниже ~75 строк панели разбиты на три страницы:

- **MARKET** — инструменты, ORDER FLOW, NATIVE CONTEXT, funding;
- **RISK** — ликвидации, danger zone, крупнейшие позиции;
- **VAULT** — HLP, heatmap, smart money.

По умолчанию страницы переключаются **с клавиатуры** (авто-ротация выключена):

| Клавиша | Страница |
|---|---|
| `1` / `m` | MARKET |
| `2` / `r` | RISK |
| `3` / `v` | VAULT |
| `4` / `a` | ALL |
| `Tab` / `n` / `Space` | следующая |
| `0` | вернуть авто-режим |

`--tui-page` задаёт стартовую страницу, `--tui-rotate N` включает авто-смену
каждые N секунд (по умолчанию `0` — только клавиши). Единый экран ALL требует
очень высокого терминала (~75 строк).

### Вариант с uv

Если uv установлен, можно запускать supervisor напрямую:

```powershell
uv run python scripts/serve.py
```

Первый запуск создаст окружение; версии зависимостей зафиксированы в `uv.lock`.

### Внешний screener на нативном API

Архитектура по умолчанию — unified: нативный hub и отдельный screener. Для ручного
запуска задайте режим в обоих процессах:

```powershell
$env:PULSE_UNIFIED="1"
$env:PULSE_API_URL="http://127.0.0.1:8431"
uv run hyperdata api --port 8420
uv run hyperdata-screener --api-url http://127.0.0.1:8420 --port 8421
```

Без `PULSE_UNIFIED=1` эти команды запускают явный legacy-режим. В unified screener
читает `/v1/attention`, `/v1/snapshot` и `/v1/candles`, не открывает собственные
биржевые сокеты; направленный AI не запускается. Подробности, parity-прогон и статус
миграции: [native-migration.md](native-migration.md).

### Настройка AI

Укажите `GEMINI_API_KEY` в `.env`, чтобы включить независимый анализ. Модель выбирается через `GEMINI_MODEL`. В unified режиме ключ используется для контекстных разборов и selective AI; направленный AI не запускается. В legacy режиме без Gemini направленный штатный сигнал сохраняется как `HYPERDATA_ONLY`, и панель продолжает работать.

Telegram включается флагом `--notify` при наличии `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Для обычного браузерного запуска используйте локальный адрес и оставьте `HYPERDATA_API_KEY` пустым. При включённой аутентификации ко всем маршрутам, включая HTML, необходимо передавать заголовок `X-API-Key`.

### Ручная установка

Если скрипт не подходит, те же шаги можно выполнить вручную:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
if (!(Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe scripts\serve.py
```

### Если что-то не так

- `Python 3.12+ not found` — установите Python с [python.org](https://www.python.org/downloads/) и откройте новый терминал.
- Порт занят — запустите с другим портом: `.\start.ps1 --port 8500`.
- Нет сигналов AI — проверьте `GEMINI_API_KEY` в `.env` и перезапустите приложение.
- Нужен чистый журнал — укажите `.\start.ps1 --journal .\scalper-test.sqlite`.

Для OpenRouter задайте в локальном `.env`:

```dotenv
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=ваш_ключ
OPENROUTER_MODEL=google/gemini-3.5-flash-lite
```

В `OPENROUTER_MODEL` можно указать другую модель с поддержкой [Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs). После изменения `.env` перезапустите скринер.

`HYPERDATA_DATA_DIR` задаёт каталог состояния HyperData и журнала. По умолчанию на Windows это `%LOCALAPPDATA%\hyperdata`. Используйте один экземпляр приложения на журнал.

## Архитектура

Данные и анализ разделены на два процесса:

- `hyperdata api` — единственный источник биржевых данных. В unified режиме `HyperDataHub` держит L2 и широкий обзор, а исполнения читает из Market Pulse (`PulseObservation`); собственные trade-подписки Hyperliquid/Binance отключены. Наружу отдаются `/v1/*` и WebSocket, включая `/v1/attention` с планом.
- `hyperdata-screener` — независимый анализ. Читает `/v1/attention`, `/v1/market`, `/v1/snapshot` и `/v1/candles`, не открывает биржевых сокетов; ведёт журнал, план attention, контекстные разборы, Telegram и веб-панель `/scalper`.

В unified режиме screener не создаёт направленных кандидатов и не запускает
`analyze`/`deliver`; работают относительное внимание, контекстные разборы и единая
очередь `CardOutbox`. Каждый показатель сохраняет источник, время последнего
наблюдения, единицу и качество. Старый направленный контур (Контур A/B, Top-20,
Gemini-очередь) доступен только в явном legacy-режиме `--without-pulse`.

Ликвидации приходят из native API: подтверждённые события OKX/Bybit (и поглощения Hyperliquid через HLP) отделены от эвристических крупных принтов. Сводка за час доступна в рыночном контексте, панели и TUI. Скринер использует публичные рыночные данные и аналитические запросы модели; операции с ордерами отсутствуют.

Расширения используют существующие зависимости HyperData, включая aiohttp, Rich и python-dotenv, а также SQLite из Python. Для Gemini используется [официальный API структурированных ответов](https://ai.google.dev/gemini-api/docs/structured-output). Веб-панель работает в aiohttp внутри screener, без отдельных биржевых подключений. Cryptofeed и CCXT здесь не требуются.



## Активность для скальпинга

> В unified режиме набор инструментов задаёт план attention, а не Top-20.
> Описание ниже относится к legacy-режиму.

- В legacy-набор по-прежнему входят 20 контрактов по 24-часовому объёму. В таблице по умолчанию выше стоит ускорение ленты. Объём можно раскрыть в дополнительных метриках.
- Скорость ленты и число сделок берутся из штатного потока HyperData. Темп к норме — отношение числа сделок в живом окне к медиане 14 закрытых свечей той же длины, которые не пересекаются с живым окном. Всплеск ленты отмечается от 2× и при не менее чем 10 сделках.
- NATR(14) в процентах рассчитывает TA-Lib на закрытых свечах Hyperliquid. Всплеск диапазона отмечается, если True Range последней закрытой свечи не меньше 2× предыдущего ATR. Недоступные и устаревшие метрики не участвуют в детекторе.
- Появление всплеска даёт кандидату приоритет среди событий одного сканирования. Оценка направления HyperData остаётся штатным выводом Order Flow. Ускорение и волатильность сами по себе направления не задают.


## Opportunity Filter и бюджет AI

> Разделы ниже описывают явный legacy-режим (`PULSE_UNIFIED=0` или
> `--without-pulse`). В unified автоматические направленные кандидаты, очередь
> `jobs` и `deliver` не создаются; работают контекстные разборы и selective AI.
> Актуальная схема: [unified-system.md](unified-system.md).

Обнаружение события отделено от допуска к модели. Переходы OFI, нейтральные состояния и повторы остаются в журнале и Dashboard. Автоматические кандидаты:

- Подтверждённое движение: rank 3–4, свежая цена, лента и стакан, приемлемый спред.
- Ранний импульс: направленный OFI от 0,6, темп от 2× локальной нормы, минимум 10 сделок и независимое подтверждение. Подтверждение — изменение цены в сторону потока больше одного спреда и 0,01% либо дисбаланс стакана от 0,25 в ту же сторону. OFI и темп считаются одной семьёй данных.

Режим `economical` допускает только подтверждённые движения. `balanced` добавляет ранние импульсы, `research` снижает порог их темпа до 1,5×, сохраняя независимое подтверждение. Ранние кандидаты получают преимущество в очереди. Пороговые значения стартовые, их эффективность ещё предстоит измерить.

По умолчанию: `SCALPER_AI_MODE=balanced`, `SCALPER_AI_HOURLY_LIMIT=40`, `SCALPER_AI_COOLDOWN_SECONDS=300`, `SCALPER_AI_EARLY=true`, `SCALPER_AI_EXPERIMENTS=false`. Эти настройки доступны в блоке «Отбор AI и общий бюджет» Dashboard. Сохранённая в SQLite политика имеет приоритет над начальными значениями окружения.

Лимит действует на скользящие 60 минут и включает автоматические, ручные, контрольные и завершившиеся ошибкой запросы. Резервирование происходит непосредственно перед обращением к провайдеру, история сохраняется после перезапуска. Одновременный кандидат другого окна того же инструмента отклоняется; cooldown общий для 1m/5m. Дополнительные экспериментальные запросы требуют явного включения и тоже расходуют бюджет. Максимум при постоянной нагрузке — 960 запросов за 24 часа для лимита 40/час.

Свежесть и условия отбора повторно проверяются перед отправкой. Кандидаты старше 45 секунд для 1m и 120 секунд для 5m удаляются из очереди без AI, сохраняя причину. Отсутствие API-ключа не создаёт AI-задания. Модель получает метрики второго окна как контекст, но не направление HyperData или решение фильтра.

Telegram имеет отдельный допуск: значимые находки и ранние импульсы могут получить информационное уведомление независимо от наличия слота AI. Обычный рыночный шум не отправляется. Статус «анализ выполняется» появляется после резервирования бюджета; очередь, пропуск и ошибки показаны отдельно. Итог редактирует исходное сообщение. В legacy-режиме `/analyze BTC 1m` запрашивает текущий снимок из Top-20 вручную; свежесть, общий бюджет и cooldown сохраняются. В unified `/analyze` работает по текущему пакету наблюдения. `/report` остаётся доступным. Периодический дайджест выключен (`HYPERDATA_DIGEST_SECONDS=0`); положительное значение включает его с указанным интервалом.

В SQLite добавлены `ai_selection`, `ai_requests`, `candidate_observations` и `scalper_settings`. Все новые события, включая отклонённые, сохраняют исходный снимок и наблюдения через 1/5/15 минут. Для AI сохраняется отдельная оценка от фактического снимка анализа: ожидание в очереди не сдвигает исходную точку проверки фильтра.

Чтобы проверять экономию, сравнивайте число обнаруженных событий, допусков и фактических запросов за сутки, а затем причины отклонений и результаты отклонённых событий на каждом горизонте. Средний абсолютный ход и доля движений ≥ NATR помогают замечать потерянные крупные движения. Сравнение AI / Rule Engine / Consensus показывает независимые решения на одних событиях с успешным ответом AI. Время расчёта и размер выборки важны: новые наблюдения дозревают за 15 минут, отчёт обновляется раз в минуту; исторические пропуски до обновления не восстанавливаются. Число запросов — мера нагрузки, денежная стоимость и токены не рассчитываются.

## Качество оценок AI

Раз в минуту приложение в фоне пересчитывает последние 24 часа из SQLite. Панель показывает статистику для выбранного окна 1m или 5m. Для каждого направленного вывода сравниваются mark в момент снимка и наблюдение через 1, 5 или 15 минут. Совпадение направления считается верным, движение в обратную сторону — неверным. Неизменная цена, ожидание и отсутствие наблюдения выделяются отдельно. Нейтральные выводы, нехватка данных, технические ошибки и пропущенные запросы учитываются в числе попыток. Один вывод может быть верным на одном горизонте и неверным на другом. Комиссии и исполнение сделок в расчёт не входят. В разрезе триггеров дополнительно видны верные и неверные оценки по горизонтам и медианная задержка от обнаружения до завершения попытки с размером выборки.

При запуске с `--notify` в настроенном Telegram-чате команда `/report` выводит оба окна, а `/report 1m` и `/report 5m` — одно окно. Бот читает команды через long polling. Этот режим требует, чтобы токен не использовался активным webhook или другим читателем обновлений.


## Контекст 15m и парная проверка

Запрос AI получает второе короткое окно, когда оно доступно, и контекст 15m по закрытым свечам Hyperliquid. Старший блок содержит NATR, изменение за четыре свечи, диапазон этих свечей и положение последнего закрытия внутри него. 15m не создаёт отдельного запроса или торгового сигнала. Вход помечает роли метрик, отделяя направление потока от интенсивности, волатильности и ликвидности.

При явном включении `SCALPER_AI_EXPERIMENTS=true` первая и затем каждая десятая подходящая успешная оценка после запуска может получить контрольный запрос с тем же снимком и без блока 15m. Основная оценка публикуется первой. Контроль использует общий лимит запросов и может увеличить ожидание следующего события. Для сравнения HyperData, AI без 15m и AI с 15m используется первая доступная mark после завершения обоих запросов. Верные и неверные направления считаются на горизонтах 1, 5 и 15 минут. Оценки без направления и пропуски выделяются отдельно, пары с ошибкой провайдера исключаются из сравнения направлений. Раздел доступен в веб-панели и Telegram-отчёте.


## Профиль инструмента и описание ситуации

SQLite сохраняет регулярные снимки обычных окон, включая тихие. Для каждого отслеживаемого инструмента и окна 1m/5m берётся один снимок возле границы интервала, если есть свежие показатели. Профиль пересчитывается в фоне и показывает число наблюдений, медиану и P90 за последние 7 и 30 дней. Минимум для медианы и P90 — 20 валидных значений на показатель. Профиль очищается после 30 дней и накапливается с момента включения сбора. Доступная история добавляется как контекст AI.

Панель и уведомления показывают наблюдаемые факты и развёрнутую характеристику AI. Характеристика связывает реакцию цены, поток сделок, ликвидность и фон старших окон, объясняет существенные расхождения и ограничения данных. Короткая условная гипотеза появляется отдельным блоком при достаточной опоре на факты. Telegram выбирает событие по обнаруженному всплеску или развороту потока с движением цены в ту же сторону. Факты для подходящего события отправляются независимо от очереди AI. Когда характеристика готова, бот редактирует то же сообщение по идентификатору Telegram. AI анализирует зафиксированный снимок этого уведомления. Порядок доставки `finding-v4` объединяет находки по инструменту в одно сообщение на пять минут. Второй таймфрейм и повышение силы на уже показанном таймфрейме дополняют это сообщение. Характеристика AI относится к исходному снимку. Сравнение направленных оценок остаётся в экспериментальном отчёте.

Теневой порог 1m требует движения цены от 0,25% и 1,5 NATR. Отчёт сравнивает число находок и показывает, у скольких контрольных событий с движением от 0,5% за пять минут не было строгой находки по тому же инструменту в пределах ±60 секунд. Эксперимент не меняет правила отправки.


## Сила находки

Скринер по умолчанию сортирует инструменты по силе находки. При равном ранге выше показывается более быстрое ускорение ленты.

- Фоновая — нет признаков выраженной активности.
- Заметная — зафиксирован всплеск, но движение цены может быть небольшим.
- Выраженное движение — есть всплеск или сильный поток, и цена уже прошла в сторону потока не меньше максимума из 0,10%, одного NATR и четырёх спредов.
- Сильное движение — оба всплеска, подтверждение потоком и движение не меньше максимума из 0,20%, полутора NATR и четырёх спредов.

Широкий спред или отсутствие свежего стакана ограничивает ранг уровнем «Заметная». Без свежей цены или ленты ранг недоступен. Telegram отправляет только два старших уровня при соблюдении условий уведомления. События старше 45 секунд для 1m и 120 секунд для 5m пропускаются перед анализом и повторно проверяются перед отправкой. Это стартовые пороги версии `finding-v2`. Ранг описывает уже наблюдаемое движение. Отчёт сравнивает его последствия отдельно от `finding-v1`.


## Журнал решений и проверка рангов

Скринер сохраняет кандидатов с исходным снимком, версией правил и сменой решения, включая фильтры, очередь, паузы и доставку. Повторная проверка одного и того же условия без изменения состояния не добавляет новую запись. Если кандидат дошёл до анализа, журнал связывает его с итоговым снимком и уведомлением.

После подтверждённой доставки скринер в течение пяти минут наблюдает mark. За точку отсчёта берётся первый свежий mark после доставки. Заметным считается абсолютное отклонение от него не меньше NATR, записанного в снимке анализа. Используются полученные снимки mark, поэтому краткий пик между ними может не попасть в измерение. При отсутствии NATR или разрывах покрытия более 30 секунд результат исключается из доли. Отчёт показывает размер выборки и медианную задержку по рангу и версии. Сбор начинается с включения журнала решений.


Контрольные окна выбираются раз в 15 минут среди фоновых наблюдений со свежими лентой, ценой и стаканом, без заявки в очереди AI. По завершённым сигналам за 24 часа подбираются отдельные завершённые контроли за 7 дней: тот же инструмент и таймфрейм, время суток в пределах двух часов, NATR от половины до удвоенного NATR сигнала. Пересекающиеся пятиминутные интервалы исключаются, один контроль используется один раз за расчёт. Это сопоставление наблюдений, поэтому при поступлении новых контрольных окон пары могут меняться. В веб-отчёте также есть разбивка по задержке доставки: до 15 секунд, 15–45 секунд и более 45 секунд.


## Контекст BTC

Для каждого контракта, кроме BTC, панель показывает корреляцию Пирсона по 36 последовательным совпадающим доходностям закрытых свечей 5m. Цена закрытия текущей незавершённой свечи в расчёт не попадает. При нехватке совпадающих наблюдений, просрочке или нулевом разбросе показатель недоступен. В карточке показаны изменения BTC и инструмента за последнюю общую свечу. Блок передаётся AI и отображается в Telegram только для двух старших рангов при наличии данных. Он не меняет ранг и не участвует в определении направления.


## Фаза движения

Фаза считается отдельно от силы находки. Для инструмента и окна скринер отслеживает смену стороны потока или появление нового всплеска при направленном потоке. Первое наблюдение после запуска или разрыва данных служит исходным состоянием. При наблюдаемом начале фиксируются mark, время и NATR. Подтверждение требует движения от 0,5 NATR и трёх свежих наблюдений с удержанием стороны потока и темпа. От 2 NATR движение отмечается как далеко ушедшее. Ослабление отмечается после отката от 0,5 NATR от максимума и трёх наблюдений с падением темпа или нейтральным потоком. Эти пороги стартовые.

Фаза, возраст и расстояние от начала видны в панели и сохраняются вместе со снимком анализа. В Telegram фаза включается в уведомление, когда начало наблюдалось. AI получает измеримые возраст, расстояние и откат от пика в NATR из того же снимка. Если начало не наблюдалось, модель получает соответствующий статус. Текущий трекер начинает наблюдение заново после перезапуска; сохранённые снимки остаются в истории.


## Теневые пороги

Каждый свежий снимок сравнивается по трём вариантам: текущие пороги, всплеск ленты от 1,5× и подтверждение ценой от 0,15% и 1,25 NATR. Считаются появления находок двух старших рангов. Повтор активного состояния ограничен, используются только фактические снимки и последующие mark-цены. Теневой отсчёт начинается при обнаружении, а рабочий отчёт доставки — после уведомления. Теневые варианты не вызывают модель и не отправляют Telegram. Сводка за 24 часа доступна в веб-отчёте, исходные записи хранятся до 30 дней.
